# パフォーマンス変更と検証手順

## 変更点

- 合成・黒背景・透明の3出力はすべて維持する。Metalのfinishを3ディスパッチから1ディスパッチに統合し、線形光での発光・残像・履歴更新を共有する。色変換と出力の書き込みは各モードの従来式を維持する。
- 画像処理のみのモードではVisionマスクの転送とサンプリングを省く。発光がゼロまたはエフェクトOFFの場合はダウンサンプルと2方向のぼかしを省く。
- 頂点アップロード用Metalバッファをセッション内で再利用する。両コマンドバッファの完了を同期的に待つ現在の契約を前提とする。外部クライアントが保持し得る出力IOSurfaceは再利用しない。
- CPU輪郭処理でマスク領域を再利用し、追跡・ランキング・選択・平滑化の不要な確保とハッシュ検索を減らす。数値演算の順序は既存のままにする。音声FFTではHann窓を共有し、入力の先頭消去を1バッチにまとめる。
- 過負荷による拒否は受理済みフレームのチケットを無効化しない。完了した入力IDのチケットを解放する。
- サービスのフレーム統計に `analysisMS`、`contourMS`、`drawMS` を追加する。これらはCPU側時計による経過時間（GPU完了待ちを含む）であり、GPU単体の時間ではない。設定変換等を含む全体は従来の `processingMS` を参照する。

## 回帰チェック

```sh
bash scripts/test-core.sh
# 同一コンパイラ・同一フラグで変更前と比較する
bash scripts/test-core.sh 047f4b8903cc8d356909daa144b417db0e1fa57d
```

静止、移動、検出途切れ、シーク、リセット、複数形状・色モードの人工入力を試す。頂点・統計のダイジェストを比較する。タイミングは同じ機器で複数回計測し、実映像のp95とは区別する。ダイジェストは同一コンパイラでの比較を意図し、異なるCPU・コンパイラ間の一致を要求しない。

## macOS実機での受入

- `scripts/build.sh --obs` でアプリ・サービス・CLI・OBSをビルドし、`docs/verification.md` の短いチェックを再実施する。
- 同一入力・プリセットで各出力の色、アルファ、残像、発光OFF/ON、画像解析のみ/Vision併用、シーク・解像度変更を比較する。
- 1080p/30fps、実写、複数OBS入力でウォームアップ後の処理時間・フレーム欠落率・メモリを測定し、変更前と比較する。連続運転と外部基準の遅延も確認する。

この文書は検証方法であり、実測済みの高速化率を主張するものではない。
