# 開発仕様と構成

2026-10-21の統合開発仕様書v1.0を要件ベースラインとする。個人利用のApple Silicon専用アプリ。対象OSはmacOS 14以降、OBSビルド基準は32.2.2。

## モジュール

| 場所 | 責務 |
| --- | --- |
| `app/` | SwiftUI、Metalプレビュー、カメラ・動画入力、Rec.709正規化、プリセット、MIDI、書き出し操作 |
| `core/` | C++20の曲線抽出、フロー補間、安定ID、弧長予算、シード付き配置、4形状、色、GPU頂点 |
| `engine/` | Metalのエッジ・動き・線・ブルーム・残像・合成、Vision、FFT、AVFoundationの録画・書き出し |
| `shared/` | バージョン付きXPC契約、IOSurface輸送、設定の検証・補間、再接続、入力リング |
| `service/` | 独立レンダーサービス、入力セッション、最新フレーム優先、録画と操作ログ、OBS制御 |
| `obs/` | libobsのフィルタ・独立ソース、Graphics API、シーン参照、音声ミックス、フェイルセーフ |
| `cli/` | オフライン書き出し、サムネイル、短い動作確認用デモ |
| `scripts/` | ビルド、個人用ヘルパー登録、OBSプラグイン導入 |

アプリとOBSは`jp.meowkawaii.KiraRaki.render`のMach ServiceへNSXPCConnectionで接続する。同一ユーザーの接続だけを許可する。IOSurfaceのNSSecureCodingを使い、グローバルな整数IDによる共有は行わない。入力は3枠で、応答前に同じ領域を再利用しない。

OBSからの入力はGraphics APIでテクスチャへ描画し、3枠のステージングを介してBGRAをコピーする。推論完了待ちはOBSの描画スレッドで行わない。サービスは同じ入力ID・PTS・設定リビジョンの結果を共有し、一度の解析から合成・黒背景・透明の3出力を作る。フィルタが既にある入力を独立ソースで参照する場合、その加工前解析を再利用し、線を二重に解析しない。

## 処理

1. 入力ID、フレーム番号、PTS、取り込み時計、色・アルファ情報を付与。
2. ファイル／カメラのBGRAをRec.709へ正規化。動画の姿勢変換を適用。
3. Metalで輝度、勾配、非最大抑制、テクスチャ、ブロックマッチングの動きを算出。
4. Visionを非同期に実行し、前景／人物の境界を融合。既定では検出途切れを画像処理で補う。
5. 稜線を両方向にたどって長い曲線を作り、点ごとのフロー、端点・途中の形の照合、方向合わせで安定IDを引き継ぐ。欠けた画素は隣接画素がない場合に限り、進行方向・接線が整合する2画素以内を橋渡しする。
6. 曲線の弧長を予算とし、ランダム・特徴・動きの比率とシードで採択。
7. 稲妻、有機スプライン、直交グリッチ、断片化を混合。空間的な折れ曲がりの間隔と、時間的な変形速度を分ける。点ごとの動きへアタック／リリースをかけ、局所的な強さと線内の不均一な包絡を掛け合わせる。断片化は長い連続区間単位とする。
8. 接合部を共有する連続した帯状の線を描く。鋭角の接合は伸びすぎないよう制限する。線形光で線・縮小ブルーム・残像を合成し、premultiplied BGRAに出力。

初期値は線幅3px、変形45%、密度35%、更新4Hz、線の長さ420px、ギザギザの間隔48px、動きへの反応100%、線内の強弱90%。寸法は1080pを基準に解像度へ追従する。線の採択は安定IDとシードに固定し、更新頻度を変えても曲線全体を再抽選しない。設定は全体共通で、形状・領域・発生位置の混合は独立に操作する。シークや入力切替で追跡・残像・音声履歴をリセットする。

## 音声と制御

48kHz、2048点FFT、512点ホップ。RMS、20〜250Hz、250〜2000Hz、2000〜12000Hz、スペクトルフラックスを計算する。音声入力は動画、明示的に選択したOBSミックス、無音。マイクやシステム音をアプリから自動取得しない。

音声マッピングはゲイン、最小・最大、アタック、リリース、反転を持つ。MIDIはCC／ノートをLearnし、パラメータ値を変更する。UI、MIDI、ランダム化、プリセットの変更はサービスへ送信し、録画中はPTS基準の設定スナップショットとして順番に記録する。プリセット補間はライブとオフラインで同じ関数を使う。

OBSは入力一覧と各KiraRaki項目をサービスへ公開する。アプリからの対象・出力モード・ミックス変更をプラグインが非同期で取得する。フィルタの解析対象は追加先に固定し、独立ソースの参照元を変更できる。

## 保存契約

- プリセット: `schemaVersion=1`。追加された`strokeLength`・`jaggedSpacing`・`motionResponse`が旧プリセットにない場合は既定値で補う。未知のバージョン、不正な型、NaN、パレット、マッピングを検証する。初期値と数値範囲の正本は`KRDefaultPreset`と`KRValidatePreset`。
- フレーム: `protocol=1`、`sourceID`、`frameID`、`ptsNS`、`ingestNS`、出力モード、色・アルファ記述、IOSurface。
- 操作ログ: `timestampNS`、`eventSequence`、`sourceType`、`parameterPath`、`preset`、残像リセット規則。
- マニフェスト: アルゴリズム版、開始PTS、記録区間、原本／クリーン映像の参照とSHA-256、シードを含む初期設定、OSとVision情報、欠落と完了状態。

原本への参照は保持する。クリーン映像はProRes 422 HQ、加工済み録画は選択したコーデックを使う。録画が失敗した場合、未完了状態を残す。再現時は入力ハッシュを確認し、録画した区間だけを読み、イベントをPTSへ適用する。高品質処理ではフレームを間引かず、エンコーダーの準備を待つ。

輪郭・変形アルゴリズムの版は0.2.0。版の正本は`KRAlgorithmVersion`で、サービス情報・録画・再現の照合に共通で使う。0.1.0の操作ログは見た目が変わるため新版では再現を拒否し、旧版で開く。旧プリセットの読み込みは継続する。

## 負荷と障害

処理時間の移動平均と復帰ヒステリシスにより、AI頻度、解析解像度、フロー探索範囲、ストローク数、ブルーム解像度の順に負荷を下げる。元のプリセット値は変更しない。適応レベルを表示する。

サービス内で古くなった待機フレームを破棄する。切断・応答停止から再接続し、OBSフィルタは元映像へ、独立ソースは透明へ戻す。循環参照は描画しない。入力のないセッションは解放し、ウィンドウが閉じていて録画／OBSの要求もない場合、不要なGPU処理を止める。

目標は1080p/30fps、入力からOBS合成出力までp95 200ms以下。内部の処理時間・転送時間だけでこの目標を満たしたとは判定しない。30分・2時間試験、外部基準の遅延、A/V同期、熱条件、OBS 33 RCの互換性は実機受入の項目として残す。
